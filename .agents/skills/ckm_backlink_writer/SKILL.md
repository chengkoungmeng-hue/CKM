# 外鏈推廣文章撰寫指引

適用平台：Medium、Substack、Blogger、Threads。每次產出必須一次給齊該平台所需的**全部欄位**，讓發佈者複製貼上即可完成，不用回頭補問。

## 站別設定（動工前先確認是哪一個站）

| 項目 | ckmkh.com | 其他站 |
| :--- | :--- | :--- |
| 業務 | 金邊柬中宴席外燴 | 動工前向使用者確認 |
| 語言 | 100% 高棉文 | 依站別確認 |
| 讀者尊稱 | `លោកអ្នក` | 依站別確認 |
| 團隊自稱 | `យើងខ្ញុំ` | 依站別確認 |
| 內頁連結來源 | `src/content/blog/` | 該站的文章目錄 |
| 外鏈帳本 | `Docs/backlink_ledger.md` | 該站的帳本 |

**§0 的連結策略、§1 的不替業主承諾原則、§3 的輸出格式、§4 的帳本紀律，三個站共用。** 語言、口吻、業務內容依站別替換。

不同站的外鏈**不要互相連結**，除非業務上真的相關 —— 交叉連結自有站點是明顯的人為訊號。

## 0. 連結策略（先讀這節，其餘都是執行細節）

外鏈的價值來自兩件事：**平台頁面自己能被收錄**，以及**它把權重傳給你指定的頁面**。以下三條規則保護這兩件事。

### 0.1 不要設 canonical 指向 ckmkh.com

**這是舊版指引的錯誤，已修正。** 舊版要求每篇外鏈文章都把 canonical 設成 `https://ckmkh.com`。那等於宣告「這篇是官網首頁的複製品」，結果是：

- 平台頁面不會被獨立收錄，也就不會排名
- 你花時間寫的文章拿不到任何自然流量
- 外鏈的權重傳遞大打折扣

**正確做法依內容來源而定：**

| 情況 | canonical 怎麼設 |
| :--- | :--- |
| 文章是**為該平台原創**（預設，建議走這條） | **不要設 canonical**。讓它自己排名、自己累積權重，再傳給官網 |
| 文章是官網既有文章的**轉載** | canonical 指向官網那篇的**確切網址**，不是首頁 |

只有真正轉載時才設 canonical，而且要指到對應的那一篇。

### 0.1b 寫新文章，用「引用」把讀者帶過去

外鏈文章**必須是為該平台重新寫的原創內容**，不是官網文章的搬運。連結的形式應該是**引用（citation）**：在論述需要佐證、或讀者會想深入的地方，自然地指向官網那一篇。

這比另外兩種常見做法都好：

| 做法 | 問題 |
| :--- | :--- |
| 整篇轉載官網文章 | 重複內容，平台頁面不會排名 |
| 原創但硬塞連結（「更多資訊請看這裡」） | 讀者不會點，Google 看得出來是為連結而連結 |
| **原創 + 語境內引用** | 讀者真的會點，因為那裡正好是他想知道更多的地方 |

**操作方式**：外鏈文章講一個較廣的主題，遇到某個需要展開但會離題的點時，就引用官網那篇專門講它的文章。

例如外鏈文章談「金邊婚宴籌辦的四個決策點」，寫到菜單那一段時：

> ការជ្រើសរើសម៉ឺនុយ ៨ មុខ មានតក្កវិជ្ជាច្បាស់លាស់របស់វា — ដំណាក់កាលនីមួយៗមានតួនាទីខុសៗគ្នា។ ការវិភាគលម្អិតអំពី[រចនាសម្ព័ន្ធម៉ឺនុយ ៨ មុខប្រពៃណីខ្មែរ](https://ckmkh.com/blog/01-traditional-8-course-wedding-menu/) បានពន្យល់ពីដំណាក់កាលទាំង ៤ យ៉ាងច្បាស់។

連結出現在讀者**正好想知道更多**的位置，錨文字描述的是目標頁的實際內容 —— 這樣的連結既自然又有轉換價值。

**反例**（不要這樣寫）：文章最後補一句「សូមទស្សនាគេហទំព័ររបស់យើងខ្ញុំ [CKM](https://ckmkh.com)」。那是廣告，不是引用。

### 0.2 連結指向內頁，不要全部指向首頁

首頁已經是站內連結最多的頁面，再灌externallinks 效益遞減。**外鏈應該把權重送到需要幫助的頁面。**

每篇外鏈文章嵌入 **1 到 2 個**指向 `ckmkh.com` 的連結：

- **第一個連結**：指向與文章主題最相關的**內頁**（例如寫月餅就指 `/tanghuot/`，寫菜單就指 `/blog/01-traditional-8-course-wedding-menu/`）
- **第二個連結**（可選）：指向首頁 `https://ckmkh.com`

寫作前先讀 `src/content/blog/` 確認要指哪一篇，並確認該網址**結尾有斜線**（`trailingSlash: 'always'`，少了會吃一次 301）。

### 0.3 錨文字必須分散

同一組錨文字重複出現在多個外部網域，是最典型的人工外鏈訊號。**每篇用不同的錨文字**，並在帳本中記錄用過哪些。

分散的方式：

- 品牌型：`ចេង គួងម៉េង`、`CKM`
- 主題型：`សេវាកម្មម្ហូបការនៅភ្នំពេញ`、`ម៉ឺនុយម្ហូបការ ៨ មុខ`
- 自然語句型：`អានបន្ថែមនៅទីនេះ`、`ព័ត៌មានលម្អិតអំពីការរៀបចំម៉ឺនុយ`

**不要**每篇都用 `សេវាកម្មធ្វើម្ហូប CKM`。

### 0.4 發佈節奏

三個平台同一天各發一篇、而且主題相近，看起來就是同時操作的。**分散開來**：一週最多 1 到 2 篇，不同平台間隔幾天，主題也錯開。

## 1. 品牌口吻（與 ckm_blog_writer 一致）

外鏈文章仍然代表 CKM，同一套規則適用：

- 讀者尊稱 **`លោកអ្នក`**，團隊自稱 **`យើងខ្ញុំ`**
- 零誇大：禁止「第一」「最強」「無敵」「神級」等
- 100% 高棉文正文，**不要**在括號附上英文或中文翻譯
- **不替業主承諾**：不寫價格、不寫最少桌數、不寫交期、不保證任何營運細節。一律導向「請透過 Telegram 或電話洽詢」
- 不寫小費、打包剩菜、殺價等損及宴席尊榮感的話題

### 文字完整性（會被 CI 擋下的錯誤）

Gemini 等模型產出的高棉文常混入**泰文、中文、日文、希伯來文**片段，Hanuman 字型無法渲染，讀者看到的是豆腐方塊。實際發生過的有 `หัวใจ`、`วัฒนธรรม`、`環境的控制與使用醬料調配提升風味`，以及緬甸文母音混進 `ក_ន` 中間。

**產出後必須逐字檢查：每個字元都必須是高棉文、拉丁字母或標準標點。** 站內有 `scripts/check_content.py` 做同樣的檢查，可以參考它的白名單邏輯。

## 2. 平台發佈規格

### 2.1 Medium

| 欄位 | 規格 |
| :--- | :--- |
| Title | 100% 高棉文，含主題關鍵字與地理詞 |
| Subtitle | 100% 高棉文，**100–140 字元**（上限 150） |
| Body | 600–1000 高棉字，嵌入 1–2 個依 §0.2 選定的連結 |
| Image Alt | 100% 高棉文，描述畫面內容 |
| Tags | **僅限英文**，5 個。例：`Catering`, `Cambodia`, `Phnom Penh`, `Weddings`, `Food` |
| Canonical | **依 §0.1 判斷**。原創文章請留空 |

### 2.2 Substack

| 欄位 | 規格 |
| :--- | :--- |
| Title | 100% 高棉文，建議 60 字元內 |
| Subtitle | 100% 高棉文，100–140 字元（用於電子報摘要） |
| Body | 同 Medium |
| SEO Title | 60 字元內高棉文 |
| SEO Description | 140 字元內高棉文 |
| Image Alt | 上傳後點圖片設定填入 |
| Canonical | 位於 Post Settings → SEO Options。**依 §0.1 判斷** |

### 2.3 Blogger

| 欄位 | 規格 |
| :--- | :--- |
| Title | 100% 高棉文 |
| Search Description | 100% 高棉文，100–140 字元（右側面板欄位） |
| Body | 同 Medium |
| Permalink | **僅限英文/拼音**，連字號分隔。例：`wedding-menu-planning-phnom-penh`。務必選 Custom Permalink，否則 Blogger 會產生亂碼網址 |
| Labels | 3–5 個，高棉文與英文皆可 |
| Image alt/title | 在 HTML 檢視中補上 |

---

### 2.4 Threads

Threads 不是部落格平台，規格完全不同：

| 欄位 | 規格 |
| :--- | :--- |
| 內文 | 500 字元上限。一則講**一個**具體重點，不要塞摘要 |
| 連結 | 一則最多 1 個。Threads 的連結多半不傳遞權重，**價值在於引流與品牌，不是 SEO** |
| 串接 | 需要更多篇幅時用回覆串接，不要硬塞進單則 |
| 圖片 | 直式或方形（動態牆以直式為主），不要用 16:9 |

**不要把部落格文章的摘要貼上 Threads。** 它的閱讀情境是滑動中的社群動態，需要的是一個能獨立成立的觀點。

## 2.5 來源多樣性（比平台數量重要）

Medium、Substack、Blogger **同屬一類**：免費部落格平台。在三個同類來源上發文，搜尋引擎看到的是一種模式重複三次，不是三個獨立背書。

對在地生意而言，**本地引用的價值高於全球部落格平台**。優先順序：

1. **本地名錄與商家檔案** —— Khmer24、Google Business Profile、在地黃頁
2. **地圖服務** —— Google Maps、OpenStreetMap
3. **社群檔案** —— Facebook 專頁、Telegram、Threads
4. **同業與在地媒體** —— 婚顧、場地、在地生活媒體
5. 免費部落格平台 —— Medium / Substack / Blogger

前四類 CKM 已有部分（見 `Layout.astro` schema 的 `sameAs`）。**擴充時往 1–4 走，不要再增加第四個部落格平台。**

NAP（名稱／地址／電話）在所有名錄中必須**一字不差**地一致，包含高棉文寫法。不一致會讓 Google 判定成不同商家。

## 3. 輸出格式

**同時提供 HTML 與 Markdown 兩種版本。** Blogger 等平台從 Markdown 直接貼上會殘留樣式（常見的是黑色背景區塊），HTML 版可避免。

圖片若有生成，用 PowerShell 複製到使用者的 `Downloads` 資料夾，並在回覆中附上下載路徑與對應的高棉文 alt text。

## 4. 外鏈帳本

**寫作前先讀 `Docs/backlink_ledger.md`**，確認新文章的目標關鍵字、標題角度、連結目標**都沒有和既有紀錄重複**。

產出後立即新增一筆，欄位如下：

| 編號 | 發佈日期 | 平台 | 標題 | 目標關鍵字 | **連結目標頁** | **使用的錨文字** | 發佈狀態 | Live URL |

比舊版多了兩欄 —— **連結目標頁**和**錨文字** —— 因為 §0.2 和 §0.3 要靠它們才能檢查是否過度集中。

發佈狀態只有兩種：`待發佈` 或 `已發佈`。已發佈的必須填入 Live URL，否則無法驗證外鏈是否真的存在。

> 目前帳本中 001–003 三筆自 2026-08-13 起停在「待發佈」。開新文章前先確認這三篇的狀態。
