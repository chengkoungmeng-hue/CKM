# CKM 部落格文章撰寫指引

當您需要撰寫、修改或檢查 ckmkh.com 的高質感柬埔寨文部落格文章（位於 `src/content/blog/*.md`）時，請嚴格遵守以下指引。

## 1. 溫和謙遜的品牌口吻與零誇大原則

品牌創辦人為低調的華裔柬埔寨人，非常注重真誠、誠信與客客氣氣的態度，切忌使用宣賓奪主或誇大不實的推銷用語。

- **提供協助，而非推銷**：文章應著重於解決讀者在籌辦婚禮、選擇菜單、規劃預算時的實際疑惑，而非強烈推銷。
- **嚴禁誇大詞彙**：絕對禁止使用「第一」、「最強」、「神級美味」、「無敵」等具有宣傳炒作意味的字眼。
- **謙虛的專家角色**：以一位擁有 60 年深厚經驗、謙遜熱心的老顧問身分，向讀者分享實用的籌辦智慧。
- **少用具體數據與硬數字**：對外網站文案應**儘量少用或不用具體數據與硬規格數字**（例如：**嚴禁寫出 "4°C-60°C"、"50-100 KVA" 等具體規格**）。文案專注於展現**溫暖、貼心、高奢感與嚴謹品質**，將具體技術數據與規格留給業主在 Telegram / 電話一對一諮詢時向客戶說明與溝通。
- **在地化的客氣稱呼**：
  - 稱呼讀者/客戶時，請使用尊稱：**"លោកអ្នក"**（您/Respected You），絕不能用一般的 "អ្នក"。
  - 自稱團隊時，請使用謙稱：**"យើងខ្ញុំ"**（我們/We，代表謙遜與熱忱的團隊）。
  - 語氣特徵：**嚴謹、細心、客氣、親切**。

### 1.1 高棉在地文化與籌辦實務三原則

1. **尊重長輩與傳統禮節 (ការគោរពចាស់ទុំ)**：柬埔寨婚宴極度重視長輩（មេបា / ចាស់ទុំ）的感受。菜單建議必須強調照顧長輩口感（如湯品軟爛、低糖、鮑魚/燕窩湯），並平衡年輕賓客的現代喜好。
2. **乾季與雨季氣候因應 (រដូវប្រាំង / រដូវវស្សា)**：針對戶外帳篷或住宅辦桌（Housewarming），必須考慮金邊氣候特點（乾季散熱與防曬、雨季防漏水與地台加高）。
3. **在地生活實務解答 (Borey 報備、稅務與停車)**：FAQ 區塊應切中在地實務需求（如：បុរី 園區報備、វិក្កយបត្រពន្ធអាករ VAT 稅務發票、現場停車安保協調）。

### 1.2 嚴禁宣稱業主無法確定能做到的硬體、系統與菜色承諾 (Promotional Boundaries Mandate)

本網站旨在協助業主宣傳與行銷其餐飲生意。由於我們無法確認或保證業主的實際營運細節與硬體設備規格，**全站所有部落格文章與頁面文案嚴禁包含以下承諾與宣称**：

1. **嚴禁宣稱「廚房設備現代化 / 智慧科技設備」**：禁止描繪自動化電晶片烤箱、智慧控溫監控系統、高科技數位廚房硬體等。統一回歸「60 年老字號ចុងភៅចាស់វស្សា 傳統烹飪工藝與細心嚴謹 Caring 手藝」。
2. **嚴禁宣稱「可自由無限創新菜色 / 各國跨國融合料理」**：禁止承諾無限量自由研發無國界料理、國際無菜單跨國融合等。統一聚焦於「經典 8 មុខ ខ្មែរចិន 柬中傳統頂級宴席菜單、熱騰騰湯品與尊榮長輩口感」。
3. **嚴禁宣稱「數位系統線上預訂、線上付款與線上選擇方案」**：禁止宣稱網站或 App 可提供線上刷卡付款、自動化線上點餐系統、數位 APP 自動劃位與選擇方案。統一指引客戶「透過 Telegram 或電話直連諮詢，由團隊提供一對一親切說明與專屬報價」。
4. **圖片 100% 柬埔寨在地化 (Local Khmer Imagery Mandate)**：全站文章封面圖與內文插圖，必須採用符合金邊與柬埔寨真實婚宴、辦桌、傳統辦席、在地主廚與高棉禮節的在地化圖片，嚴禁使用西式歐美科技廚房或不相干的外國素材。
5. **嚴禁代業主承諾「提供含稅發票 (VAT Invoice) / 具體發票稅務承諾」**：我們無法替業主決定稅務與發票開立細節，全站文章與 FAQ 嚴禁主動承諾開立含稅發票或寫死發票細節。統一引導客戶「透過 Telegram 或電話與團隊專人聯繫諮詢」。

### 1.3 嚴禁小費、打包與低俗尷尬話題 (Zero Tipping, Leftover Packing & Cheap Bargaining Mandate)

依照華人傳統與柬埔寨高階婚宴儀節，CKM（ចេង គួងម៉េង）身為 60 年名店老字號，文章與 FAQ 區塊**嚴禁包含任何損及主辦人尊榮感、小家子氣或有損品質形象的尷尬議題**：

1. **嚴禁提及「小費 / 服務人員額外報酬」**：
   - 絕不討論賓客或主辦人是否該給服務人員小費或額外紅包。
   - 所有問答與內文統一強調「CKM 專業團隊早已包含完善服務，且以至誠禮貌關照每一位賓客與長輩」。
2. **嚴禁提及「打包剩餘食物 / 帶回家」**：
   - 絕不討論外辦人員是否協助打包或剩飯處理。
   - 相關 FAQ 統一替換為「食材 100% 鮮採控溫保障、現場熱菜及時上桌與熱騰鮮美口感保障」。
3. **嚴禁提及「低價殺價 / 廉價省錢」**：
   - 絕不使用「便宜」、「殺價」、「省錢」等廉價詞彙。
   - 統一使用「預算合理規劃」、「CP 值極佳的尊榮套餐配置」與「透明物超所值的 60 年口碑保障」。
4. **FAQ 正向尊榮導向 (VIP Dignity FAQ Standard)**：
   - 所有常問問題 (FAQ) 必須圍繞在：**「長輩飲食照顧 (ការគោរពចាស់ទុំ)」、「宴席流程順暢 (ចង្វាក់នៃការបម្រើអាហារ)」、「新鮮食材與嚴謹衛生 (អនាម័យនិងសុវត្ថិភាព)」與「Borey 報備與場地協調」**。

### 禁用硬體與英文技術詞彙對照表

文章內文**嚴禁直接出現英文單字與工程技術縮寫**，必須統一替換為流暢口語的柬埔寨文：

- **`Catering`** ➔ 替換為 **`សេវាកម្មធ្វើម្ហូប`**（外辦宴席服務）或 **`សេវាកម្មម្ហូបការ`**（婚宴餐飲）
- **`VIP`** ➔ 替換為 **`ភ្ញៀវកិត្តិយស`**（尊榮賓客/貴賓）
- **`Brand Identity`** ➔ 替換為 **`អត្តសញ្ញាណរបស់ក្រុមហ៊ុន`**（企業品牌形象）
- **`Buffet`** ➔ 替換為 **`អាហារប៊ូហ្វេ`**（自助餐）
- **`Cocktail / Finger food`** ➔ 替換為 **`អាហារសម្រន់ស្រាលៗ`**（精緻茶點輕食）
- **`50-100 KVA`** ➔ 替換為 **`កម្លាំងអគ្គិសនីខ្ពស់ (៥០-១០០ គីឡូវ៉ាត់)`**（高功率電力設備）
- **`LED`** ➔ 替換為 **`អំពូលភ្លឺច្បាស់សន្សំសំចៃថាមពល`**（節能高亮度燈具）
- **`Generator`** ➔ 替換為 **`ម៉ាស៊ីនភ្លើងបម្រុង`**（備用發電機）
- **`HACCP`** ➔ 替換為 **`អនាម័យនិងសុវត្ថិភាពម្ហូបអាហារ`**（食品清潔與衛生安全）
- **`FAQ`** ➔ 標題統一使用 **`## សំណួរដែលសួរញឹកញាប់`**，嚴禁寫成 `(FAQ)`

## 2. 文章結構與 AI 搜尋優化

為了讓文章更易於被智慧型搜尋引擎（如 Google 智慧摘要）收錄，並方便讀者快速獲取答案，文章結構須遵循以下格式：

1. **文章字數**：每篇文章字數至少在 1,200 字以上（以柬埔寨文計算）。
2. **開頭核心摘要**：
   - 文章開頭前言下方，統一使用標題 **`## ចម្លើយរហ័ស`**（Quick Answer），提供一段 40 到 80 字的簡短解答，直接回答讀者最關心的核心問題。
3. **標題層級規範**：
   - 每篇文章只能有 **一個大標題（H1）**。
   - 副標題請使用 Markdown 的 `##`（H2）與 `###`（H3）。
   - 請確保所有副標題的字距與行距足夠寬鬆，防止柬埔寨文字上方的變音符號（如 ើ, ឹ, ី）與上方的文字重疊。
4. **豐富的排版元素**：
   - 每篇文章必須包含至少 **一個對比表格**（例如：預算分配表、套餐內容對比、桌數估算表）。
   - 包含實用的**檢查清單**（例如：婚禮籌辦進度清單、菜單選擇要點）。
   - 文章結尾須附帶 **`## សំណួរដែលសួរញឹកញាប់`**（常見問題區塊），提供 3 到 4 個具體的問答。

## 3. 文章頂部設定區域（Frontmatter）

每篇 `.md` 文章的開頭，必須包含以下基本設定欄位，請以標準格式書寫：

```yaml
---
title: "文章主標題 (100% 柬埔寨文)"
seoTitle: "搜尋引擎優化標題 - CKM Premium Catering"
description: "文章簡介 (120-160 字，簡要描述文章重點以吸引點擊)"
coverImage: "../../assets/grounded_images/ckm_blog_NN.png"
date: 2026-07-04
targetGeo: "Phnom Penh, Cambodia"
authoritySignals:
  - "帶有可查證事實的信任標籤"
  - "每篇應與該篇主題相符，不要 15 篇共用同兩句"
featured: false
draft: false
---
```

### 欄位注意事項

- **`date` 為必填。** 缺少時 `blog/[slug].astro` 會回退成建置當天，導致每次部署都把長青
  文章重新標記為「今天發佈」。這是明確的日期操縱訊號。
- **`coverImage` 實際命名是 `ckm_blog_NN.png`**，不是 `blog_xx_cover_khmer.png`。
  `src/assets/grounded_images/` 裡有四代殘留檔名，請以現有文章實際引用的為準。
- **`target_keyword` 與 `slug` 會被 Zod 丟棄。** `src/content.config.ts` 沒有定義這兩個
  欄位，而 `z.object()` 預設剝除未知鍵；網址是由 `entry.id`（檔名）決定的。寫了不會生效，
  要嘛在 schema 補上並真的去讀它，要嘛不要寫。
- 可用欄位以 `src/content.config.ts` 為唯一準則：`title`、`seoTitle`、`description`、
  `date`、`coverImage`、`targetGeo`、`authoritySignals`、`schemaType`、`category`、
  `featured`、`draft`。

## 3.5 內文配圖規範

- 每篇文章在中段插入 **一張** 內文圖：

  ```html
  <img src="/images/blog_NN_inline_khmer.webp" alt="（高棉文，描述畫面內容）" class="w-full aspect-[16/9] object-cover rounded-sm my-8 shadow-md border border-slate-200" />
  ```

- **編號必須與文章自己的編號一致。** 第 12 篇曾引用 `blog_01_inline_khmer.webp`，而它自己
  的 `blog_12` 圖從未被使用。`scripts/check_content.py` 會擋下這種錯配。
- 圖片為 16:9（1600×900）。版面用 `aspect-[16/9] object-cover`，正方形圖上下會各被裁掉
  約 28%。
- `alt` 寫高棉文，描述畫面實際內容，不要塞關鍵字。

## 3.6 內部連結（每篇必做）

**每篇文章正文至少嵌入 3 個指向其他 `/blog/` 文章的連結。** 稽核時發現第 13、14、15 篇是零內部連結 —— 它們拿不到任何站內權重，也留不住讀者。

- 連結要放在**語境內**：寫到某個需要展開的點時，指向專門講它的那一篇
- 錨文字描述目標頁的內容，不要用「按這裡」「閱讀更多」
- 網址結尾**必須有斜線**（`/blog/06-signature-dishes/`），少了會吃一次 301

## 3.7 事實一致性（寫之前先 grep）

同一件事在站內只能有一種說法。稽核時抓到的實例：

| 事實 | 曾經出現的版本 |
| :--- | :--- |
| 鮑魚湯熬煮時間 | `៨ ទៅ ៨៦ ម៉ោង`（8–86 小時，數字本身就壞了）／`១២ ទៅ ២៤`／`៨ ដល់ ១២` |
| 預訂前置時間 | `៦ ទៅ ៨ ខែ`／`៤ ទៅ ៦ សប្តាហ៍`／`២ ទៅ ៣ ខែ` |
| 烤乳豬室溫保存 | 第 6 篇寫 3 小時，第 4 篇的食安表寫 2 小時 |

**寫任何具體數字前，先 `grep` 站內既有說法。** 對不上就別寫，或先統一。

目前已定案的：

- 預訂前置時間：**`២ ទៅ ៤ សប្តាហ៍`**，結尾一律接「請聯繫我們確認日期」。不要重新引入旺季說法
- 熬煮時間、上菜順序：**視食材大小與各家習慣而定**，不給固定數字
- 荷葉飯寫 **`បាយខ្ចប់ស្លឹកឈូក`**（`ខ្ចប់` 是「包」，也是 `កញ្ចប់` 的字根）

菜名一律與 `src/data/homeData.ts` 完全一致。

## 3.8 高棉文字元完整性

AI 產出的高棉文常混入**泰文、中文、日文、希伯來文、緬甸文**片段。Hanuman 字型渲染不出來，讀者看到的是豆腐方塊。實際發生過的：

- 泰文 `หัวใจ`、`วัฒนธรรม`、`รากผักชี`
- 中文整句 `環境的控制與使用醬料調配提升風味`
- 希伯來文 `עוד`、緬甸文母音夾在 `ក_ន` 中間
- 同形字：泰文 `า` 混充高棉 `ា`、中文 `。` 混充 `។`

這類錯誤**用黑名單擋不完**（列了泰文漏中文，列了中文漏希伯來文）。判準是白名單：**每個字元都必須是高棉文、拉丁字母或標準標點。**

寫完務必執行：

```bash
python scripts/check_content.py
```

它同時檢查外來字元、重複詞、已知錯字、以及高棉文叢集結構（腳音 `្` 後面有沒有接子音）。CI 在 commit 前會以 `--strict` 再擋一次。

## 3.9 結論放在 FAQ 之後

稽核發現第 02、03、04、10、11、12 篇的 `## សេចក្តីសន្និដ្ឋាន`（結論）排在 FAQ **之前**，導致文章的最後一段話是某個行政備註。

**正確順序：** 正文 → `## សំណួរដែលសួរញឹកញាប់` → `## សេចក្តីសន្និដ្ឋាន`

結論是離 CTA 最近的一段，它應該收在讀者準備行動的地方。

## 3.10 authoritySignals 要有可查證的事實

這兩個標籤會渲染成文章封面圖正下方的信任徽章 —— 是手機讀者最先看到的東西。稽核發現 15 篇反覆使用同兩句空話，訓練讀者忽略它。

- ❌ `សេវាកម្មប្រកបដោយវិជ្ជាជីវៈ`（專業服務）、`បច្ចេកទេសចម្អិនកម្រិតខ្ពស់`（高級烹飪技術）
- ✅ 帶數字、名稱或具體事實，**而且每篇要與該篇主題相符**

## 4. 排版與文字空白行規範

為了讓文章外觀整潔並通過系統檢查，請遵守以下 Markdown 排版細節：

- **標題前後留空行**：所有的標題（如 `#`、`##`、`###`）上方與下方都必須留有一行空白行。
- **列表前後留空行**：所有的項目列表（如 `*` 或 `1.`）與前後的普通文字段落之間，必須留有一行空白行。
- **程式碼與區塊前後留空行**：所有以三個反引號（```）包围的程式碼區塊前後，必須留有一行空白行。
- **嚴禁多重空行**：文章中不允許出現連續兩行以上的空白行。
- **結尾空行**：檔案的最末尾必須有且僅有一個換行符號（空一行）。
